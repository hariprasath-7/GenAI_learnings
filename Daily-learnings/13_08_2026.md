1. **What Is a Vector Database?** — A Vector DB stores and searches embeddings. A record can include an ID, vector, original text, and metadata.
2. **Vector Database Architecture** — A typical flow is query → embedding → optional metadata filter → index → similarity calculation → ranking → top results.
3. **Metadata Filtering** — Metadata is extra information such as category, year, or language. Filters limit which vectors are allowed in a search.
4. **CRUD Operations for Vectors** — Create, read, update, and delete vector records. If content changes, regenerate its embedding. Upsert means update if it exists, otherwise create.
5. **Why Vector Indexes Are Needed** — Checking every vector is exact but expensive at scale. An index narrows the search to useful candidates.
6. **Approximate Nearest Neighbor (ANN)** — ANN searches intelligently through a smaller candidate space. It trades a little possible recall for speed, lower cost, and lower latency.
